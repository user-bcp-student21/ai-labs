# HU-01: Reducir la persistencia del token de autenticación

## Origen

- Componente: `web`.
- ID: `H-WEB-01` — Token de sesión almacenado en `localStorage`.
- Estado en `HALLAZGOS.md`: `Pendiente`.
- Evidencia: `web/src/app/login/login.component.ts:47`; `web/src/app/dashboard/dashboard.component.ts:36,75`.

## Contexto

El cliente guarda el token de sesión en `localStorage`, desde donde queda accesible a JavaScript del mismo origen. El hallazgo señala un riesgo potencial de exposición; no afirma que haya ocurrido robo del token. El flujo observado comprende iniciar sesión, usar la sesión para consultar tareas y cerrar sesión.

## Ajustes necesarios

- Evitar persistir el token de autenticación en `localStorage`.
- Mantener el flujo observado de login, consulta de tareas autenticada y cierre de sesión.
- Decidir y documentar una alternativa de manejo de sesión antes de implementar. La matriz no prescribe cuál; no se fija aquí una tecnología de almacenamiento.
- No incluir tokens, secretos ni credenciales en código, logs, documentación o pruebas.

## Criterios de aceptación

1. Una prueba de login exitoso verifica que el token no se escribe en `localStorage`.
2. Una prueba del dashboard verifica que, con una sesión válida, la solicitud de tareas conserva el header `Authorization: Bearer` sin leer el token desde `localStorage`.
3. Una prueba sin sesión verifica que no se solicita la lista de tareas y que la UI navega a `/login`.
4. Una prueba de cierre de sesión verifica que la sesión deja de estar disponible y que una consulta posterior de tareas no reutiliza la sesión anterior.
5. Las pruebas usan valores ficticios aislados y no imprimen ni registran el valor del token.

## Evidencia esperada

- Pruebas automatizadas de login, acceso autenticado a tareas, ausencia de sesión y cierre de sesión, con resultados registrados.
- Inspección del código que confirme que el token ya no se persiste ni se obtiene desde `localStorage`.
- Confirmación de que el comportamiento de login, consulta de tareas y logout se conserva.
